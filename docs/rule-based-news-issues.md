# 비-AI 뉴스 이슈 생성 정책

## 목적

Solar API를 사용할 수 없는 기간에도 실제 수집 기사만으로 이슈별 뉴스 묶음과 출처 기반 요약을 제공한다.
이 방식은 새로운 해석을 생성하지 않으며 기사에 포함된 문장을 발췌한다. 화면에는 `기사 기반 자동 발췌`로
표시하고, AI 요약과 구분한다.

## 처리 범위

- 대상: 실행 시각 기준 최근 24시간 뉴스, 최대 120건
- 입력: 제목, 수집사가 제공한 요약문, 언론사, 발행 시각, 원문 URL
- 주요 이슈 조건: 중복을 제외한 기사 2건 이상
- 출처 조건: 서로 다른 언론사 2곳 이상. 동일 언론사만 있으면 기사 3건 이상일 때 허용
- 최대 저장 이슈: 기사 수가 많은 순서로 8개

단독 기사와 조건을 만족하지 못한 묶음은 주요 이슈로 올리지 않는다. 원문이 없는 정보나 외부 지식을
추가하지 않는다.

## 1. 정규화와 중복 제거

제목을 소문자로 변환하고 `[속보]`, `[단독]`, `(종합)` 등의 표식과 문장부호, 반복 공백을 제거한다.
다음 중 하나에 해당하면 같은 기사로 간주하고 먼저 발행된 한 건만 사용한다.

- 본문 요약을 포함한 `content_hash`가 동일함
- 제목 토큰 Jaccard 유사도가 0.82 이상임

## 2. 특징 추출

각 기사에서 다음 특징을 추출한다.

- 기업: 매일 수집하는 KRX 종목 마스터의 기업명
- 기관·국가: 연준, FOMC, 한국은행, 금융위원회, 미국, 중국, ECB, OPEC 등
- 주제: 반도체, 거시·금리, 환율, 에너지, 중국, 증시, 실적
- 사건어: 실적, 수주, 공급, 계약, 인수, 합병, 규제, 관세, 금리 인상·인하, 투자, 증설 등
- 제목 토큰: 조사성·보도 관용어를 제외한 2자 이상의 한글·영문·숫자 토큰

키워드 사전은 `backend/app/services/rule_based_issues.py`에서 버전 관리한다.

## 3. 군집화

최신 기사부터 기존 묶음과 비교하는 보수적인 greedy 방식이다. 아래 앵커 조건을 먼저 만족해야 점수를
계산한다.

- 공통 기업·기관이 하나 이상 있음, 또는
- 공통 주제와 공통 사건어가 있고 제목 유사도가 0.12 이상임

점수는 공통 엔티티 4점, 공통 주제 1.5점, 공통 사건어 1.5점, 제목 유사도 최대 4점으로 계산한다.
기존 묶음 중 최고 점수가 4점 이상일 때만 합친다. 따라서 `반도체`처럼 넓은 주제 하나만 같다는 이유로
서로 다른 기업이나 사건을 합치지 않는다.

## 4. 대표 기사와 제목

핵심 엔티티·사건어가 많이 포함되고 요약문이 충분한 기사를 대표 기사로 정한다. 이슈 제목은 문장을
새로 생성하지 않고 대표 기사 제목을 그대로 사용한다. 상세 화면에서는 대표 기사를 먼저 표시하고
묶음에 포함된 모든 기사 제목, 언론사, 발행 시각과 원문 링크를 제공한다.

## 5. 추출 요약

기사 요약문을 문장으로 나누고 다음 기준으로 점수를 계산한다.

- 공통 기업·기관·사건어 포함
- 날짜, 가격, 비율 등 숫자 포함
- 최신 기사에 포함

유사도가 높은 반복 문장을 제거한 뒤 상위 2문장을 선택하며 최대 240자로 제한한다. 사용할 수 있는
문장이 없으면 대표 기사의 요약문, 그것도 없으면 대표 기사 제목을 사용한다. 감성은 추정하지 않고
항상 `neutral`로 저장한다.

## 6. 실행과 저장

`collect-news` Job은 뉴스 저장 직후 규칙 기반 이슈 생성을 실행한다. 필요하면 `build-issues` Job만 별도로
실행할 수 있다. 결과는 기존 `issue_summaries` 테이블에 다음 메타데이터로 저장한다.

- `model`: `rule-based-extractive`
- `prompt_version`: `issue-cluster-v1`
- `article_ids_json`: 대표 기사를 첫 번째로 둔 출처 기사 ID 목록

새 실행에서 더 이상 유효하지 않은 규칙 기반 이슈는 삭제한다. Solar API가 준비되면 같은 이슈 묶음을
입력으로 사용해 요약문만 AI 결과로 교체할 수 있으며, 기사 목록과 원문 출처는 그대로 유지한다.

## 한계와 운영 점검

- 동의어 사전에 없는 표현은 같은 사건이어도 분리될 수 있다.
- 기업명이 일반 단어와 같은 경우 잘못된 엔티티로 잡힐 수 있다.
- 여러 사건을 한 기사에서 다루면 가까운 묶음 하나에만 배정된다.
- 매일 상위 이슈의 오분류·과다 병합·누락을 확인하고 키워드 및 임계값을 조정한다.

정확도를 수치로 관리하기 전까지는 과다 병합보다 분리를 우선한다. 금융 정보 서비스에서는 서로 다른
사건을 하나로 합쳐 잘못된 인과관계를 암시하는 위험이 더 크기 때문이다.
